# TSH Screens Blob Codec Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pure-JS model and codec (`tshBlob`) for `screens_config_base64` of INT-TSH2 / INT-TSG2 keypads that decodes every TSH Soft sample and re-encodes it byte for byte, with limit errors instead of truncation.

**Architecture:** Four CommonJS modules in `work/working/src/renderer/app/desktop/tshEditor/`: format constants, byte helpers, typed widget payloads, and the blob decoder/encoder. No React, no Node `Buffer`, only `Uint8Array`, `TextEncoder`/`TextDecoder`, `atob`/`btoa` (available in the Electron renderer and in Node 22). Anything the decoder cannot read exactly is kept as raw bytes and written back unchanged. Tests run with `node --test` on 89 TSH Soft samples copied into a fixture file, with the existing `tools/tsh-blob.mjs` parser as an independent oracle.

**Tech Stack:** Node 22.22.1 (system, tests), Electron 44.9.3 renderer (Chrome 152) as the runtime target, `node:test` + `node:assert/strict`.

**Spec:** `PROJEKT-TSH-EDYTOR.md` (step 1 of "Kolejność wdrożenia", "Warstwy kodu" point 1, "Sprawdzenie" first bullet); format: `PROJEKT-TSH.md` sections 2.1–2.4. Read both before starting.

## Global Constraints

- Scope: step 1 only. No editor route, no UI, no asset extraction, no wiring into `KeypadSettingsScreen`. Nothing in the app `require`s the new modules yet, so esbuild does not bundle them and the shipped artifact does not change.
- Byte order big-endian everywhere; texts UTF-8 with a one-byte length in bytes (`PROJEKT-TSH.md` 2).
- Global header `0x160` bytes, directory at offset 6, entries of 9 bytes (`u8 id`, `u16 offset`, `u16 length`, `u32 sum`), at most 38 entries; records contiguous from `0x160` in directory order theme, screensaver, user screens, additional screens.
- Padding: `0xab` up to a multiple of 32, 0–31 bytes, never a full 32.
- Checksum (`PROJEKT-TSH.md` 2.4): over `d[0..d[1]]`, stored at `d[d[1]+1]`; order: widget sums, then header sum, then directory `u32` (plain byte sum of the whole record including its checksums).
- Limits: ≤ 16 user screens; ≤ 38 directory entries; header length `hl` ≤ 255 and widget length `L` ≤ 255 (high byte 0); theme image exactly 32 bytes padded with spaces (longer is refused); resolutions only 1024×600 (TSH2) and 480×272 (TSG2). The encoder returns errors and never truncates.
- Code style: follow `work/working/src/renderer/app/desktop/deviceTable/deviceTableModel.js` (CommonJS, `Object.defineProperty(exports, "__esModule", { value: true })`, `exports.a = exports.b = undefined;` list, `var`, double quotes, 2 spaces, ≤ 120 columns). Header comment per file, one comment per function (why, returns), English. Format facts are named constants with a source comment (`PROJEKT-TSH.md` section).
- Issues and errors carry a `code` (stable, `UPPER_SNAKE`) and an English `detail` for logs. User-facing text is mapped from `code` in the editor step (i18n), not here.
- Tests: `node:test` + `node:assert/strict`, files `*.test.js` under `work/working/test/unit/tshEditor/`, helpers in `work/working/test/support/`, fixtures in `work/working/test/fixtures/`. Each test file starts with a comment naming the module under test and the run command. Assert whole objects; limits below, at and above.
- Run all tests: `npm --prefix work/working/tools test` (script added in Task 1).
- Commits on `main` (local repo, no remote), stage by path; no `Co-Authored-By` or other AI trailer, no AI mention in messages (core rules §2 "No AI traces in git").
- `REJESTR-ZMIAN.md`: no entry in this plan. The register lists behaviour changes against the original; a module nothing calls changes no behaviour. The wiring step (editor route) adds one entry that lists these files as "nowy, kopiuj bez zmian". `CHANGELOG.md`: one bullet under `### Documentation` of `## [Unreleased]` (Task 5), no version header, because the shipped artifact does not change.
- `tools/tsh-blob.mjs` stays as the reverse-engineering CLI and the independent test oracle (it was reviewed independently on all samples); it is not switched to the new codec, so a bug in the codec cannot hide itself. Its only change is an import guard (Task 5).

## Review Focus

- A user's real blob containing a record or widget the samples never had (type 15, length ≥ 256, wrong checksum): it must survive decode → encode unchanged; pinned by the raw-preservation tests in Task 3 and Task 4.
- Screens with very many widgets: the record or blob outgrows `u16` length/offset; the encoder must refuse (`RECORD_TOO_LARGE`, `BLOB_TOO_LARGE`), not wrap; pinned in Task 4.
- Polish (multi-byte UTF-8) names and texts at the 255-byte limit: the limit counts bytes, not characters; pinned by the `ą` boundary tests in Task 4.
- Model switched between TSH2 and TSG2 while the theme record still carries the other resolution (the TSH bug of sample 083 in another form): the encoder refuses (`THEME_LAYOUT`); pinned in Task 4.
- Invalid UTF-8 inside a name or text from a damaged blob: the decoder must not replace characters (that would change bytes); the record or widget data falls back to raw; pinned in Task 2 and Task 3.

## Model (shared by all tasks)

Defined as JSDoc `@typedef` in `tshBlob.js`. Colors are lowercase `"rrggbb"` strings. Fixed-but-unknown **[P]** bytes are kept as `number[]` so the encoder writes them back unchanged.

```js
/** @typedef {{ version: number, width: number, height: number, records: TshRecord[] }} TshBlob */
/** @typedef {TshScreen | TshRawRecord} TshRecord */
/**
 * @typedef {Object} TshScreen
 * @property {"screen"} kind
 * @property {number} id                 directory id (not unique: theme and saver can both be 0)
 * @property {"theme"|"screensaver"|"user"|"additional"} type   byte 17: 0, 1, 2 (3 = 2 + main), 4
 * @property {boolean} main              byte 17 bit 0x01 on a user screen
 * @property {number[]} layout           bytes 2–6 as read (theme: LCD width, height, 0x20; others 00 20 00 20 20)
 * @property {boolean} useTheme          byte 7 bit 0x80
 * @property {boolean} grid              byte 7 bit 0x10
 * @property {number} flagsOther         byte 7 without 0x80 and 0x10
 * @property {string[]} colors           bytes 8–16, three colors
 * @property {number} saverOptions       byte 18 (0x02 no clock, 0x04 no screensaver)
 * @property {string} name
 * @property {string} image              theme: trailing spaces of the 32-byte field removed
 * @property {TshWidgetEntry[]} widgets
 */
/** @typedef {{ kind: "raw", id: number, bytes: Uint8Array, reason: string }} TshRawRecord */
/** @typedef {TshWidget | TshRawWidget} TshWidgetEntry */
/**
 * @typedef {Object} TshWidget
 * @property {"widget"} kind
 * @property {number} x
 * @property {number} y
 * @property {number} type               byte 6 as stored, e.g. 0x23
 * @property {boolean} useTheme          byte 7 bit 0x80
 * @property {boolean} center            byte 7 bit 0x08
 * @property {number} size               byte 7 bits 0–1
 * @property {number} flagsOther         byte 7 without 0x80, 0x08, 0x03
 * @property {string[]} colors           bytes 8–16
 * @property {object|null} data          typed payload (Task 2) or null when not decoded
 * @property {Uint8Array} payload        payload bytes as read; written back only when data is null
 */
/** @typedef {{ kind: "raw", bytes: Uint8Array, reason: string }} TshRawWidget */
/** @typedef {{ code: string, record?: number, widget?: number, detail: string }} TshIssue */
```

`record` and `widget` in an issue are array indexes in `records` / `widgets`, never ids.

Decoder rules:
- Fatal (`blob: null`): `TOO_SHORT` (not a `Uint8Array` or < 0x160 bytes), `VERSION` (byte 0 ≠ 1), `RESOLUTION` (not 1024×600 or 480×272), `TOO_MANY_RECORDS` (byte 5 > 38), `RECORD_RANGE` (a record not at the expected contiguous offset, shorter than 22, or past the end).
- Non-fatal, record parsed normally: `DIR_SUM` (detail exactly `` `directory sum ${stored} != record sum ${real}` ``), `PADDING` (not 0–31 bytes of `0xab` to a multiple of 32).
- Record kept as `{ kind: "raw", id, bytes, reason }` plus an issue with the same code: `HEADER_LONG` (byte 0 ≠ 0), `HEADER_LAYOUT` (`hl + 2 > len` or `22 + nameLen + imageLen ≠ hl + 1`), `HEADER_CHECKSUM`, `RECORD_ID` (id byte after the name ≠ directory id), `SCREEN_TYPE` (byte 17 not in `{0, 1, 2, 3, 4}`), `NAME_UTF8` (name or image invalid UTF-8), `THEME_IMAGE_LENGTH` (theme image length byte ≠ 32), `WIDGET_LENGTH` (a widget with `L` < 16 or past the record end).
- Widget kept as `{ kind: "raw", bytes, reason }` plus an issue (`widget` = index), parsing continues after it using the full `u16` length: `WIDGET_LONG` (high length byte ≠ 0), `WIDGET_CHECKSUM`.
- A widget whose payload `decodeWidgetData` returns `null` is a normal widget with `data: null` and no issue.

### Task 4: Blob encoder with limits

**Files:**
- Modify: `work/working/src/renderer/app/desktop/tshEditor/tshBlob.js` (add `encodeBlob`)
- Test: `work/working/test/unit/tshEditor/tshBlobEncode.test.js`

**Interfaces:**
- Consumes: `encodeWidgetData` (Task 2), model builders and `patchRecordByte` (Task 3).
- Produces: `encodeBlob(blob: TshBlob): { ok: true, bytes: Uint8Array } | { ok: false, errors: TshIssue[] }`. All errors are collected in one pass; `bytes` is absent on error.

Encoder rules: widgets (`data` → `encodeWidgetData`, else `payload`; raw widget → `bytes` verbatim), then header with its checksum, then record; raw record → `bytes` verbatim; directory `u32` = `byteSum(record)`; theme image padded with spaces to 32 bytes; zeros up to 0x160; `0xab` padding. Error codes: `VERSION`, `RESOLUTION`, `TOO_MANY_RECORDS` (> 38), `TOO_MANY_USER_SCREENS` (> 16 records with `type: "user"`), `RECORD_ORDER` (screen records not in order theme, screensaver, user…, additional…; record 0 must be a theme and record 1 a screensaver unless raw), `THEME_LAYOUT` (theme `layout` bytes 0–3 ≠ blob width/height), `HEADER_TOO_LONG` (`hl` > 255), `THEME_IMAGE_TOO_LONG` (> 32 bytes), `WIDGET_TOO_LONG` (`L` > 255), `RECORD_TOO_LARGE` (record > 0xffff bytes), `BLOB_TOO_LARGE` (a record offset > 0xffff), `FIELD_RANGE` (id, x, y, size 0–3, flagsOther, saverOptions, layout of 5 bytes, colors), plus the Task 2 codes with `record` and `widget` set.
